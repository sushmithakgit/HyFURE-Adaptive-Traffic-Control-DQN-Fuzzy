## 📌 Overview

Most traffic signals run on fixed timers and treat every vehicle the same. An ambulance carrying a patient waits in the same queue as everyone else. We call this **"vehicle blindness"**, and in an emergency, the seconds it costs can decide the outcome.

**HyFURE** is a two-layer AI framework that makes traffic signals both adaptive and priority-aware:

1. **Fuzzy logic layer (strategist):** reads congestion and the types of vehicles at the junction, and decides how urgent each direction is
2. **Reinforcement learning layer (executor):** a Deep Q-Network that learns the best real-time sequence of signal phases to serve that priority while keeping overall traffic moving

The system was built and validated in **SUMO**, a microscopic traffic simulator, avoiding the cost and risk of live testing.

## 🔄 Architecture

```
SUMO intersection ─> Traffic state (counts, waiting times)
        │                         │
        │                         ▼
        │              Fuzzy priority estimator ─> Urgency score per direction
        │                         │
        │                         ▼
        │              DQN agent (state + priority scores) ─> Signal phase
        │                         │
        └────── Reward feedback ◄─┘
```

## 🧪 Methodology

### 1. Simulation Environment
- Four-way intersection in SUMO, three lanes per road, controlled through TraCI
- Vehicle classes: cars, bikes, trucks, buses and ambulances, generated by probability (bikes most frequent, ambulances least)
- Vehicle priority is inversely proportional to frequency, so ambulances rank highest

### 2. Fuzzy Priority Estimator
- Mamdani-style fuzzy inference system
- Inputs per direction: vehicle count and waiting time
- Piecewise linear membership functions (low, medium, high)
- Output: a normalized urgency score U ∈ [0, 1] for each direction (N, S, E, W), with emergency vehicles boosting priority further

### 3. Deep Q-Network Agent
- **State:** lane vehicle counts, waiting times and the four fuzzy urgency scores
- **Actions:** four discrete signal phases
- **Network:** two fully connected hidden layers (128 and 64 neurons, ReLU)
- **Training:** Adam optimizer (learning rate 0.001), experience replay, target network, epsilon-greedy exploration decaying from 1.0 to 0.05
- Minimum green time constraint for realistic switching

### 4. Reward Function

```
R = ΔW + λ·U(action) + Σ τ(priority vehicles) − P(teleport)
```

- **ΔW:** reduction in total waiting time
- **λ·U:** bonus for serving urgent directions
- **τ:** small reward for clearing priority vehicles (ambulances, buses)
- **P(teleport):** heavy penalty for SUMO teleports, which don't happen in real traffic

### 5. Signal Control Logic
- Emergency vehicle detected: green for that lane, others held
- Normal conditions: green to the most congested lane
- Low traffic: demand-based green to avoid unnecessary stops
- No vehicles: hold the current phase

## 📊 Results

Compared against a fixed-time signal and an RL-only controller (no priority awareness):

**Average waiting time by vehicle class (seconds)**

| Vehicle | Fixed-time | RL only | HyFURE |
|---------|-----------|---------|--------|
| Ambulance | ~20.5 | ~14.5 | **~2.5** |
| Bus | ~47 | worse than baseline | **~18.45** |
| Truck | ~52 | peaks above 500 | **~12.5** |

**% improvement over the fixed-time system**

| Metric | RL only | HyFURE |
|--------|---------|--------|
| Overall traffic | 69.75% | **77%** |
| Ambulance | 29% | **88%** |
| Bus | −46.35% | **64.5%** |
| Truck | 30.75% | **74.66%** |

The RL-only agent cut overall congestion but stayed vehicle-blind, and buses actually waited longer than under fixed timing. HyFURE kept the congestion gains while cutting ambulance waiting time by 88%.
